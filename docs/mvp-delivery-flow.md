# MyGuest — MVP Delivery Flow

**Status**: Functional as of June 2026. Tested end-to-end with real email delivery.

---

## 1. End-to-End Delivery Pipeline

```
Host fills Tally form
        ↓
Cloudflare Worker receives webhook
  → validates Tally signature
  → separates public data from private data
  → stores private data in KV (priv-<slug>)
  → stores submission record in KV (subm-<id>)
  → stores delivery record in KV (delivery:<slug>)
  → dispatches repository_dispatch to GitHub Actions (type: new-villa)
        ↓
GitHub Actions (generator.yml)
  → generates public guide shell (index.html) — no sensitive data
  → generates print shell (print.html) — no sensitive data, footer placeholder
  → commits to main branch
        ↓
GitHub Actions (pages.yml)
  → deploys to GitHub Pages (myguestguide.com/villas/<slug>/)
  → after deploy: calls POST /notify on Cloudflare Worker
        ↓
Cloudflare Worker (/notify)
  → reads delivery:<slug> from KV
  → derives printUrl from guestAccessUrl (.replace('/guest/', '/print/'))
  → sends delivery email via Resend to customer_email
  → email contains exactly 2 links (see section 7)
  → updates delivery record status in KV
```

---

## 2. Slug Formula

```
slug = slugify(property_name) + "-" + últimos caracteres de submission_id
```

Example: `Casa Serena` + `01JSG4J8P2K9X7` → `casa-serena-k9x7`

Rules: lowercase, no accents, spaces → hyphens, no symbols, no double hyphens.

---

## 3. KV Records Structure

| Key | Contents |
|-----|----------|
| `subm-<id>` | Full submission payload |
| `priv-<slug>` | `secrets` object (wifi_ssid, wifi_password, door_code, building_code, host_phone, house_access_private) + `guest_access.guest_access_token` |
| `intake:<slug>` | Intake record for manual review |
| `delivery:<slug>` | `slug`, `customer_email`, `guest_access_url`, `print_url`, `status` |

---

## 4. `/guest/<slug>?token=` — Secure Mobile Guide

- **Purpose**: Serves the complete guest guide with private data injected server-side.
- **Auth**: Validates `token` query param against `priv-<slug>.guest_access.guest_access_token` in KV.
- **On valid token**: Fetches `index.html` shell from GitHub Pages, calls `injectPrivateDetailsIntoBookHtml()`, returns full HTML.
- **On invalid/missing token**: Returns error HTML, no sensitive data exposed.
- **Cache**: `cache-control: no-store` — never cached.
- **Injection targets** (DOM IDs in `master.html`):
  - `private-wifi-content`
  - `private-access-content`
  - `private-contact-content`

---

## 5. `/print/<slug>?token=` — Secure Printable Guide

- **Purpose**: Serves the complete printable guide with private data injected server-side.
- **Auth**: Same token validation as `/guest/`.
- **On valid token**: Fetches `print.html` shell from GitHub Pages, calls `injectPrivateDetailsIntoPrintHtml()`, returns full HTML.
- **Injection**: Replaces `<div class="footer-note">` (the placeholder footer in `print.html`) with a private data block using CSS classes `contact-rows`, `contact-row`, `contact-label`, `contact-val`.
- **Cache**: `cache-control: no-store`.
- **Note**: `print.html` is generated by GitHub Actions with public data only. The `/print/` endpoint is where private data is added at serve time, never at build time.

**Print URL derivation**: `printUrl = guestAccessUrl.replace('/guest/', '/print/')` — same slug, same token, different path segment. No schema changes to KV needed.

---

## 6. Security Rules (Non-Negotiable)

- **WiFi, codes, host phone, house_access_private** → live only in Cloudflare KV. Never in `public/`, GitHub Pages, GitHub Actions artifacts, or committed files.
- **`print.html`** generated by GitHub Actions contains only public data. Private data is injected at serve time by `/print/` endpoint.
- **Complete client PDF** is obtained by the host opening the `/print/<slug>?token=` link and using browser `Print / Save as PDF`. The PDF is never generated, stored, or committed by GitHub Actions.
- **`render-pdf.yml`** is for demo/QA only. Blocked on non-demo slugs. Output is a workflow artifact (14 days), never committed.
- **No sensitive data in logs.** Worker must not print secrets to console.
- **All Tally input is untrusted**: HTML-escaped before rendering.
- **Tokens** live in GitHub Secrets / Cloudflare Secrets, never in the repo.

## 8. Flow Without Attachments (Auto-Dispatch)

When the Tally form has no file uploads (`existing_book_file` and `existing_book_photos` are empty):

1. Worker validates signature and parses payload.
2. Separates public data (for HTML generation) from private data (for KV).
3. Stores `priv-<slug>` and `subm-<id>` in KV.
4. Dispatches `repository_dispatch` to GitHub Actions.
5. GitHub Actions generates guide → publishes to Pages → calls `/notify`.
6. Worker sends delivery email with 2 secure links.

---

## 9. Flow With Attachments (Manual Pause)

When the Tally form includes file uploads (PDFs, Word docs, photos of existing welcome book):

1. Worker detects `existing_book_file` or `existing_book_photos` in payload (non-empty).
2. Saves submission to KV with `status: needs_manual_extraction`.
3. Saves intake record with client data for Vero's review.
4. **Does NOT dispatch to GitHub Actions.**
5. Vero reviews uploaded files manually and extracts necessary information.
6. Once extraction is complete, generation is triggered manually.

**Critical rule**: The flow must never auto-generate or auto-deliver books when files are attached. Vero reviews first.

Future: An internal Tally form (`MyGuest — Manual Extraction Review`) will allow Vero to enter the extracted data and trigger generation.

## 10. `/notify` Endpoint — Post-Deploy Notification

- **Trigger**: Called by `pages.yml` after GitHub Pages deploy completes.
- **Auth**: `Authorization: Bearer <NOTIFY_SECRET>` header.
- **GitHub Actions step** (`Notify Worker`):
  - Extracts slug from last commit message: `git log -1 --pretty=%s | sed -n 's/^Generate villa page for //p'`
  - POSTs to `$WORKER_URL/notify` with `{ "slug": "<slug>" }`
- **Worker reads**: `delivery:<slug>` from KV, gets `guest_access_url` and `customer_email`.
- **Derives**: `printUrl = guestAccessUrl.replace('/guest/', '/print/')`
- **Sends**: Delivery email via Resend from `hello@myguestguide.com`.
- **Updates**: `delivery:<slug>` KV record with `print_url` and `status: delivered`.

**Config required in GitHub:**
- Secret: `NOTIFY_SECRET` (value: rotatable shared secret)
- Variable: `WORKER_URL` = `https://myguest-worker.veronica-perezarroyo.workers.dev`
